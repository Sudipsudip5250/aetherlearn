# Privacy, passwords, phishing awareness, and safe updates

## Objectives

By the end of this lesson, you can identify suspicious requests for secrets or urgent action, explain why unique passwords reduce the impact of reuse, and describe a safer way to handle device and application updates.

## Prerequisites

Complete DL-03 and DL-04, or understand basic apps, permissions, browsers, and links.

## Availability

This lesson is fully offline. All messages and account details in the exercises are fictional.

## Explanation

Privacy is the ability to control how information about you is collected, used, stored, and shared. Good privacy habits begin with data minimization: share only what an activity genuinely needs, review permissions, and avoid placing secrets in messages, screenshots, or public posts.

A strong account practice is to use a different long password or passphrase for each important service. A password manager can help create and remember unique credentials. Multi-factor authentication adds another check, but it does not make it safe to disclose a one-time code to someone who asks unexpectedly.

Phishing is a deceptive message or page designed to make a person reveal information, open something unsafe, or send money. Warning signs can include an unexpected request, pressure to act immediately, a mismatched sender or domain, an attachment the recipient did not expect, or a request for a password or verification code. A suspicious message should be reported through a trusted channel rather than answered through its embedded link.

Updates can fix defects and improve compatibility. Install updates through the device’s normal settings or the application’s established store or release channel. Avoid downloading “urgent updates” from a random message. Before a major change, keep an appropriate backup of important personal files.

## Worked example

Fictional message: “Your learning account will be deleted in 10 minutes. Reply with your password and six-digit code, or tap `learn-help.example.invalid` to restore access.” The message has urgency, requests secrets, and uses an untrusted link. The safer response is to avoid replying or tapping, open the service through a known bookmark or app, and report the message.

## Common mistakes

A familiar logo does not prove that a message is genuine. A lock icon in a browser does not prove that the person or organization behind a page is trustworthy. Another mistake is changing one reused password after an incident while leaving the same password on other services.

## Offline practice

Classify each fictional message as **expected**, **needs verification**, or **suspicious**. Write down the clues you used. Do not open any link. Then design a three-step response for a suspicious message: stop, verify through a trusted route, and report or delete it.

## Knowledge check

1. Should you share a one-time verification code with an unexpected caller? **No.** Treat the code as a secret and verify through a trusted route.
2. Why use unique passwords? **A breach of one service is less likely to unlock another service.**
3. Where should an urgent update be installed from? **The device’s normal settings or a trusted application distribution channel**, not an unexpected message attachment or link.

## Project or application

Create a private “safe defaults” checklist for a fictional phone. Include screen-lock protection, app-permission review, unique passwords, multi-factor authentication where appropriate, update sources, and a plan for reporting suspicious messages. Do not write down real passwords or codes.

## Accessibility notes

The lesson uses text labels and does not require color recognition. Suspicious-message examples include a written explanation of every warning sign. Learners can complete the classification exercise without opening a link or relying on timed interaction.

## Safety and responsible use

This is an S0 safety lesson. All examples are fictional. Never use the exercise to send messages, test a person, collect credentials, or imitate a real organization.
